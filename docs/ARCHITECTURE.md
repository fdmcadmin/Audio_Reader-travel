# Architecture

## Optional headphone/music coexistence (0.3.13)

`HeadphoneMusicMode` defaults off in the separate audio-output preferences. Normal playback retains Media3's existing automatic focus configuration. On enable, it pauses, validates API 31+, optional READ_PHONE_STATE and an explicit connected eligible output, switches to USAGE_MEDIA / SPEECH with automatic focus disabled, starts `CallPauseMonitor`, and updates recognized Android Auto command permissions. `ChapterSessionPlayer` guards Play/Pause/Stop/seek with the requesting session controller; book/resumption callbacks guard before canceling pending work. Phone and generic headset controls remain available. Disabling restores normal focus and the car's original commands while paused.

The monitor registers one callback per active subscription, retains callbacks strongly and unregisters removed subscriptions, plus an audio-mode listener. Unknown initial states fail closed. Telecom aggregate state is checked synchronously before Play. Call/communication activity pauses without auto-resume; an error disables the mode and restores focus. No numbers, contacts, history or audio are collected, and there is no polling loop. Permission is checked at setup, callback publication and every Play. Output presence/actual AudioTrack verification remains independently enforced. Missing outputs never clear to system routing; choosing a non-headphone output disables coexistence. Bluetooth product categories cannot distinguish a car from headphones reliably, so the UI requires owner selection by name.

At most six short control/focus events persist, with coarse controller labels and local timestamps, for user-initiated sharing beside the last output observation. Neither the event stream nor the callback state changes book text, casts, Room schema, synthesis/cache identities or progress format. Actual head-unit commands, call coverage and independent physical output routing remain device tests; native fixture injection is not a production bypass and is not exposed through session commands.

## Preferred output and local route observation (0.3.12)

`AudioOutputPreferences` is separate from narrator/book preferences and defaults to system routing. A device choice fingerprints the available sink's type/address/name; only the hash and display name persist. `AudioOutputPolicy` rejects missing or ambiguous identities and handles changed Android IDs on reconnect. The service owns the AudioDeviceCallback, preferred-device call and all Play guards, including media-session controls and internal preview/web/book starts. Reconnect never issues Play. No Bluetooth scanning, communication-device/SCO setting, new permission or global routing API is used.

The existing Media3 1.6.1 DefaultAudioSink retains its standard AudioTrack provider, wrapped only to observe Roadleaf's own AudioTrack routing callbacks through a weak reference. Actual routing is reported separately from the preference. Selected-output mismatch or an unconfirmed route after a bounded 1.5-second startup check pauses playback and preserves progress; there is no claim of zero callback latency. Device/route callbacks replace continuous polling. A short last observation updates only when its value changes; the owner explicitly shares a text-only result. No chapter or other-app playback data enters the report. Default routing leaves Android Auto/focus behavior intact. Hardware split routing remains an independent parked test.

## Per-book narrator (0.3.11)

`BookVoiceCast.narratorVoice` is an optional persisted voice ID. Empty preserves the global narrator; old JSON defaults to empty. It supplies base prose, uncertain dialogue and narrator-role speech, including the automatic narrator-first opening and Narrator only mode. Chapter viewpoints still override it when casting is enabled; an explicit Narrator chapter choice returns to the book narrator. The transient `storyVoice` remains derived and is never persisted. Automatic voice allocation reserves the book narrator; shared voice defaults avoid it. The Characters editor exposes the override and its actual preview, and respects an explicit female MC when suggesting voices. No global listening preference, Room schema or audio/cache pipeline changes are required. Device setup is an explicitly invoked Android test-helper operation, not a bundled novel default.

## Chapter viewpoint and speaker continuity (0.3.10)

The book's fixed MC binding and a chapter's prose narrator are independent. `ChapterPerspectives` keeps bounded, chapter-local named viewpoint evidence (32 chapters, 16 candidates each). Automatic selection needs at least three hits across two windows and a dominant lead over the runner-up; an explicit chapter choice, including Narrator, wins. Evidence never replaces the fixed book MC. The resolved `storyVoice` is transient. Profiles persist optional pronoun hints, the follow-viewpoint setting and up to 64 manual chapter choices with backward-compatible defaults.

`DialogueState` now retains at most 720 characters of masked, unquoted narrative and 240 characters after the last closed quote. Recent unambiguous grammatical subjects and explicit pronoun hints can resolve pronoun tags to a dedicated identity. Quoted name mentions do not become scene evidence. Named vocal descriptions, reversed speech tags, boundary-safe right-curly thought quotes and same-turn action beats extend attribution; a bare tag introducing the next quotation cannot claim the previous quotation.

`VoiceCastPlanner` can inspect up to 1,800 original characters from the already-staged following source window, only within the same chapter. This evidence can locate a trailing tag before choosing a quotation's voice. It is never emitted, consumed, learned ahead or saved in the current checkpoint. Explicit named question introductions ending in a colon can also bind a bounded series of unquoted question sentences to that person. Quoted claims, unnamed introductions, new paragraphs and subsequent prose are excluded. When a chapter narrator is resolved, unclear dialogue and Narrator-assigned roles use that chapter voice too, preventing fallback to a global narrator that may share the MC's voice. The queue stages a single following window and retains the current one through cancellation; source offsets, insertion/commit ordering and the existing cache budget are unchanged. Bounded English cues remain fallible, especially for untagged exchanges and ambiguous pronouns.

Device checks that run on a listener's own phone first write a device-private recovery file: reading, progress and listening preferences, every book's saved and learned cast, and the chapter queue. They restore it afterwards, rolling casts back where a check changed them. Reports contain metadata and counts, never story text or audio.

Supertonic synthesis requests are capped at 300 characters before entering its own splitter, while other engines retain the 550-character bound. Word/sentence boundaries and all original words remain. The upstream engine also uses a [300-character English batch limit](https://github.com/DevGitPit/supertonic-android/blob/main/app/src/main/java/com/brahmadeo/supertonic/tts/SupertonicTTS.kt). `NarrationBuffer` permits three prepared files including the current one in Battery saver when multiple assigned or automatic cast voices are available; single-voice playback stays at two and Extra buffering stays at four. The existing 64 MiB/128 MiB disk budgets remain. Debuggable builds log source offsets, voice IDs, lengths and timings for preparation diagnosis, never source text. Compact builds do not emit these traces.

`SpeechRecovery` distinguishes an inner provider deadline or stopped synthesis from cancellation of the owning playback job. Supertonic's individual completion wait is bounded at 15 seconds. An incomplete request longer than 100 characters can retry its complete wording as short same-voice phrases, joining neutral PCM under the original canonical cache identity before applying pitch once. Planning sees original paragraphs; only provider input collapses whitespace. The real-engine test verifies complete wording and exact cache reuse after recovery. A bounded reconnect/retry handles remaining stopped/timeout failures before the source span is consumed; exhausted recovery becomes a visible narration error instead of silently canceling the refill coroutine. Owner Pause/Stop and permanent focus loss still cancel immediately without a reconnect. The Android `onStop` callback now completes its pending request exceptionally rather than leaving it unresolved. Both pure cancellation tests and real-engine injected stopped/missing-callback tests cover this distinction. No failed partial WAV becomes a completed cache entry.

## Stable character voices and adaptive delivery (0.3.9)

`CharacterDelivery` separates a character's installed voice ID from delivery. Follow the story uses bounded, explicit nearby speech-tag cues: hostile delivery lowers pitch to 0.92 of the saved narrator pitch, and warm delivery restores the natural pitch. Natural and Lower tone are manual overrides. An optional lower starting tone belongs to the per-book character assignment. Narration and explicitly narrator-assigned characters stay natural. A continued quote retains both its voice and pitch across private synthesis windows.

The learner counts only unquoted, directly named actions toward the confirmed/learned MC, including configured aliases. Contradictory or unclear cues do not count. At most one attitude observation per source window changes a score bounded to −2…2; two independent evidence windows are required before the learned baseline takes priority over a configured starting tone. Friendly evidence can retire a lower baseline, and later hostile evidence can change it again. Recent replay hashes prevent repeated counting. Planning uses prior committed evidence and never changes a speaker's voice ID to express attitude. This is a limited English heuristic, not emotion generation, semantic understanding or knowledge of future chapters.

`OfflineSpeech` requests neutral rate/pitch from the engine and caches that base WAV. `WavePitch` applies non-neutral pitch locally with the already bundled Media3 Sonic processor, at speed 1, then caches a derived WAV under a separate versioned identity. This makes pitch work with providers that ignore Android's `setPitch`, without double-applying it on providers that honor it. Neutral pitch adds no conversion. Other PCM formats are streamed through the existing mono PCM16 converter; processing retains only small buffers and uses the existing cache budget. Media3 continues applying playback speed once. Pitch adjustment does not add a neural emotion model or guarantee a warmer perceived voice.

Saved casts, learned attitude evidence and pitched quote checkpoints use optional backward-compatible preference fields. Missing old fields default to Follow the story, no lower seed, zero evidence and natural checkpoint pitch. Transient effective delivery is not saved over a manual assignment. Room, source access, focus handling and permissions are unchanged.

The Characters editor offers delivery controls and a preview that leaves the saved narrator unchanged. Official friendly labels cover the ten Supertonic English voices. No book starts with a preset cast; installing the APK does not copy emulator or test settings onto a phone.

Decorative mathematical-letter website watermarks are matched through NFKC folding with an original UTF-16 index map. Only matched watermark ranges are removed; remaining story text is not normalized, and original checkpoint offsets stay intact.

## Dialogue attribution and spoken watermarks (0.3.8)

`NarrationText` version 2 removes known FreeWebNovel watermarks embedded in story lines, hidden/spaced brand variants, bounded promotion phrases and branding in the spoken title. A promotion at the beginning of a line no longer causes the remaining story on that line to be discarded. Cleanup affects synthesis text only; stored source text and original checkpoint offsets do not shift. Audio keys include the final spoken text, so affected cached speech is replaced without clearing the library/cache wholesale.

`DialogueQuotes` supplies shared straight/curly single- and double-quote boundaries for planning and masked learning. Word apostrophes and common elisions remain unquoted narration. Open-quote checkpoint characters stay compatible with existing JSON. A known continued speaker is not replaced by a generic closing pronoun tag. Local before-tags stop at sentence punctuation and quote boundaries, reducing attribution carried from an unrelated preceding sentence.

Uncertain automatic names are omitted from the effective named cast, letting an explicit local he/she tag use the shared role. Owner-assigned Narrator characters still take priority. Learning can link a named tag on one side of the same quote with an explicit pronoun tag on its other side; generic pronouns are rejected as names and a pronoun that immediately introduces another quoted turn is not attached backward. Two consistent independent windows remain necessary for a learned shared gender role. An explicit main voice is retained after the narrator-only opening even before that name has accumulated automatic evidence.

The Characters panel displays the active engine/installed locale count, resolved audition voices and duplicate-role choices. All role previews use the same sentence. Automatic male/female auditions use the available pools even if the actual first passage must stay narrator-only. Supertonic suggestions reserve distinct narrator/main/male/female IDs when enough voices exist. This is one-engine synthesis, not simultaneous use of two voice apps or an acoustic voice-distinctness guarantee.

## Automatic per-book casting (0.3.7)

New books default to Automatic. Their first unlearned source window uses only the narrator, including dialogue. `AdaptiveCast.prepare` builds an effective cast from previously committed evidence, then proposes the next immutable learned state. `NarrationService` synthesizes that window normally and commits the proposal only after all cancellable work has completed and the original source window is queued. Learning cannot consume text, change chapter IDs or introduce new playback items. Quote continuation still uses the existing checkpoint context. Reopening a learned book retains its cast rather than starting from scratch.

`LearnedCastPreferences` stores bounded names, evidence counts, likely-MC identity, engine/voice bindings and hashes of recently observed original spans. No additional chapter prose or audio is stored there. A book tracks up to 64 names and 256 recent span hashes. Exact replay/resume does not repeatedly increase evidence, and canceled planning does not mutate state. The same canonical website-book/offline-book identities used for casting separate these records. An offline-book deletion removes that book's learned state.

Local recognition uses proper names with speech tags outside quoted dialogue, plus repeated explicit pronoun/noun cues. It rejects generic pronouns as names, quoted identity claims and ambiguous gender links containing another capitalized name. Two independent tagged windows are needed for a learned shared role, and two consistent gender cues are needed; names never determine gender. A likely MC requires repeated, dominant named viewpoint cues across windows as well as dialogue evidence; the loudest or most frequent speaker alone is insufficient. The chosen likely MC stays fixed until a user override or reset. These are conservative English heuristics, not semantic understanding or reliable identification for every novel.

`AdaptiveVoices` selects only installed matching-accent voices from explicitly supported named voice families (currently Supertonic M/F). It reserves narrator, shared male/female and MC choices. Frequent supporting speakers can earn unused matching voices; existing bindings are retained. With no spare labelled voice, shared roles/narration remain. Unknown engines still learn names, but require owner-selected defaults to assign vocal gender. Existing explicit voices, character roles, aliases and confirmed MC take priority.

Voice → Characters exposes Automatic, Narrator only and My assignments only, optional overrides, and the learned names. Existing enabled 0.3.6 profiles adopt Automatic with their overrides intact; an existing narrator-only choice stays off. New manual-only choices persist explicitly. Reset is an app-only service command: stop/cancel the selected book's pending generation and save listening progress before clearing learned state. Resetting another book leaves current playback/status untouched. Learning and all synthesis stay local through the existing single engine, with no new permission, dependency, paid service or source capability.

The native full-chapter check plays the actual supported page at 1× behind Android Home, without seeking. It validates ordered source-span coverage, non-silent speech WAVs, continuous cumulative chapter position, unchanged logical chapter identity and a natural ending. Reports contain metadata/timings, not chapter prose/audio. Waveform/control checks do not constitute a human pronunciation or voice-quality assessment.

## Chapter narration and character casting (0.3.6)

`ChapterSessionPlayer` wraps the private ExoPlayer through Media3's `ForwardingSimpleBasePlayer`. Media sessions expose stable real-chapter IDs and `AUDIO_BOOK_CHAPTER` metadata, rather than a playlist entry for every synthesized window. `ChapterAudioClock` accumulates measured WAV durations, so position continues across windows. Total chapter duration remains unknown until its last window is prepared. Full-duration scrubbing is unavailable while audio is incremental; ±15/30 seconds can move within retained prepared audio, and standard next/previous select real chapters. A temporary end of prepared audio is exposed as buffering while more text remains. No full-book synthesis or unbounded audio playlist is required.

`NarrationText` cleans spoken text, separately from the original chapter text used by checkpoints. It speaks a title once without the leading Chapter number, strips exact site/navigation/footer lines from supported webpages, treats punctuation-only replies as unspoken beats, and expands a few unambiguous English abbreviations after owner overrides. `SpeechUtterances` keeps bounded sentence/word spans for the engine. Android TTS runs at a neutral base rate; Media3 applies user speed once. This preserves input words and avoids stacked speed, but does not guarantee an engine's pronunciation or prosody.

`VoiceCastPreferences` stores independent optional profiles by offline book ID or canonical website book URL. No book starts with a preset main character; casting stays off until enabled. Narrator settings remain separate. Profiles contain MC, male/female dialogue defaults, and manually assigned recurring characters with aliases/dedicated voices. Only installed offline voices from the selected engine/language are offered. Cast previews override the synthesis voice without changing the narrator preference.

`VoiceCastPlanner` uses configured names with speech tags and explicit he/she speech tags in bounded local context. It preserves curly/straight double quotes and quote state across private windows; unclear attribution stays with narration. It does not infer gender from a name or promise semantic speaker identification. Recurring-character promotion is an explicit user assignment. `CastSpeechRenderer` plans before pronunciation replacement, synthesizes sequentially through the same engine, and joins one bounded source window into one WAV. `WaveAudio` copies matching mono PCM16 samples directly, or streams PCM8/16/float32 voice formats through downmix/resampling with bounded memory. Short joins retain every sample; no leading/trailing speech trimming occurs.

Checkpoints additionally retain original span length, cumulative chapter start, audio identity and preceding dialogue context. Matching audio restores exact saved milliseconds. Voice/text/rendering changes replay only the current original span from its beginning rather than seeking old audio time into different narration. Legacy checkpoints remain readable. Cast changes save progress and stop only the matching active book; Continue reading reloads it with the new cast. Room schema remains 2 and no runtime permission or cloud service is added.

Since 0.3.5, Room schema 2 adds `WebBook` shortcuts through an additive 1→2 migration. `WebsiteLibrary` groups supported chapter URLs by book, updates the last opened chapter and preserves parsed titles when a later navigation has only a URL. `WebBookLinks` resolves shortcut identity and friendly labels without network requests or expanding source permissions. Generic website links remain browser shortcuts. Library imports its legacy last-reader URL once, and new reader navigation or Sources browser opens remember links automatically.

`WebListeningProgress` stores a checkpoint per website book in the existing private preferences, while retaining the legacy last-page fields for compatibility. Resuming a quick pick keeps that book's exact speech span and audio position. Explicit new-book/restart actions clear only the selected website book's checkpoint. Shortcuts do not contain downloaded chapter prose. The reader uses event-driven native controls around its existing WebView, with secondary actions collapsed; Library uses the shared palette in Compose.

`MainActivity` (Compose) → `LibraryViewModel` → Room DAO / `BookImporter` / `SourceRegistry`.

`MainActivity` → Media3 `MediaController` → `NarrationService` → ExoPlayer + `OfflineSpeech`.

The MediaLibraryService outlives the activity during playback. App-only custom commands manage voices/queues. Trusted system controllers and the OS-verified Android Auto package can browse local media and issue standard playback commands. `CarLibrary` maps stable book/chapter IDs to local metadata; play requests resolve those IDs into generated local audio, never arbitrary remote/file URIs. Queue replacement cancels pending rendering before rebuilding. Imported data is written before the database transaction commits.

Source boundaries are explicit: capability declarations are descriptive, policy checks are authoritative at download time and on every redirect. Adding a catalog provider means implementing `StorySource` and a specific allow policy; browser-only adapters never gain download behavior from a URL suffix. Source code does not store account passwords, cookies or source session tokens.

EPUB parsing uses Jsoup XML and HTML parsers with no external-entity fetcher. Container/package paths resolve to ZIP entries; chapter text is saved to generated internal names. Images and styling are omitted from narration. Font-encrypted EPUBs are conservatively rejected along with other encrypted EPUBs in this initial parser.

Pronunciation substitution is literal, bounded to whole words/phrases and compiled once per queue (replacements never cascade). `ChapterNarrationQueue` opens one `SpeechChunkReader` at a time and retains the current pending window plus one staged following window and the small prepared audio playlist. Peeking ahead never consumes the pending window. Synthesis, duration inspection and cancellable I/O complete before the source span is consumed and inserted into playback without another suspension. Canceled lookahead therefore retries the same text. Offsets reference original text. Audio cache keys include engine package, voice, pitch, rendering version and final speech text. ExoPlayer handles speed without resynthesis.

`ListeningPreferences` persists voice/resource settings independently of the Room schema. Draft sliders do not write preferences every frame. Voice discovery, narration and previews share a single speech engine connected lazily. `OfflineSpeech.warmUp` connects it and has the narrator voice speak one word into a discarded file, at most once per engine start. The service does this shortly after a controller connects, and whenever a webpage begins loading, so a story's first passage doesn't wait for a cold engine. Fresh starts, chosen words and paragraph starts open with short passages (up to 360, then 720 and 1,200 characters, each ending at a paragraph or sentence). Exact resumes keep their recorded passage and cached audio. Only installed offline voices are listed; an unavailable explicit choice produces an actionable error. File reads/hashes/cache maintenance run off the UI thread. Checkpoints exist only during active playback; cache scans are throttled and UI state comes from player events rather than polling.

ExoPlayer owns audio focus with generic media content attributes and unplug handling. Ordinary notification-style focus may duck volume while narration advances. Exclusive transient/call focus suppresses playback and resumes when focus returns, unless manually paused; permanent media focus loss stays paused. Pending text waits through exclusive temporary interruption. Media-library callbacks and the media-button receiver provide explicit resumption after service termination.

Extension points: OPDS2, permitted source APIs, richer manual casting, cross-book queue editing, reading view, export/backup and incremental serial updates. Add Room migrations when changing schema; destructive fallback is deliberately absent. Version 0.2 adds DAO queries and separate preferences without changing the existing schema.

## Live browser narration (0.3)

`WebReaderActivity` hosts one normal WebView and accepts supported chapter URLs through paste/share. The renderer retains important priority while hidden behind another app. No JavaScript-to-native bridge, browser-cookie import, arbitrary file access, mixed content or TLS bypass is exposed. A constrained DOM snapshot is parsed with Jsoup off the UI thread; only bounded text/metadata is sent through app-only Media3 commands. Images, common media/font resources and off-site requests are blocked except the normal verification host. First-party scripts remain available for ordinary page rendering. After a successful extraction, loading/timers stop until the next load or manual read.

The service retains current chapter text in memory and feeds the existing bounded speech queue through a `StringReader`; chapter HTML/text is not inserted into the offline library. URL/text/audio offsets persist separately. Synthesized segments use the existing bounded audio cache. A local 120-second silence file preserves media controls and audio focus during loading/preparation; it is generated once in cache, not downloaded or bundled. The page stage has a separate 30-second watchdog; local synthesis has a bounded preparation window.

When no more than 2,500 characters of a chapter remain to be prepared, the service emits an *early* tokenized navigation request for the next chapter while the current one keeps playing. The activity loads and scans that page and returns its text; the service renders the opening passage in the background (`prepareWebPage`) without touching playback, and at chapter completion starts it at once (`installWebPage`). Learning is re-read at that moment, and the opening is re-rendered only if its voices changed. Pausing keeps an early read. An early read that fails, or is still loading at chapter completion, is dropped, and the usual navigation request runs. Neither kind moves the Quick pick until the chapter's audio starts. The activity's navigation collector remains active below STARTED so placing another app in front does not itself stop handoffs. Scans start at once and inspect the existing DOM without additional page requests. Before ten seconds, a scan is used only when the page has finished loading and its chapter text has stayed unchanged for 1.2 seconds, so text a page adds after loading isn't cut off. From ten seconds, the first readable scan is used, as before, every two seconds until the 30-second limit. Next URLs must be HTTPS, same configured host, same story and exactly the next numbered chapter. Pauses/focus loss invalidate the token and cancel preparation; stale DOM callbacks cannot resume playback. A paused loading item cannot be restarted by a headset Play command. A missing activity, renderer loss or unavailable chapter fails safely; activity/renderer survival and real-site behavior require device verification. Standard media controllers can operate playback; webpage/settings commands remain app-only.

Pages read from the owner's own browser (`via` = tab) never auto-navigate: the browser reader has no control over the browser. When such a chapter ends, the service records it in `webChapterEnded`. A Play command from any controller (bubble, notification, headset) is then turned into a `browserPlayRequest` while the browser reader is connected. The reader compares the page on screen with the finished one (`BrowserContinue`): a different page is read from its saved place or the top; otherwise it asks the owner to open the next chapter. "Continue by itself" still starts the exact next chapter without Play. NovelAI entry points stay hidden until `BrowserReaderPreferences.novelAi` is set. It is set when a NovelAI link is added (Library, Sources, or sharing it to the reader, which then opens the setup steps) or when a NovelAI reading starts from the bubble.

The traffic label uses UID receive/transmit counters and updates every ten seconds only while the UI is STARTED. It is approximate aggregate app traffic (Wi-Fi plus mobile), not carrier-billed monthly cellular usage. The 0.3 change keeps Room schema version 1 and installed voice preferences unchanged.

### Explicit source reset and deletion (0.3.2)

Library Add webpage book and the reader's Load new book select a URL through `WEB_BEGIN` with navigation enabled. Read loaded chapter uses the same acknowledged command before extracting the current DOM. The service cancels rendering, persists valid old progress, clears player items/readers and the stored queue, then returns a new selection token. The critical clear is non-cancellable; internal pause events cannot cancel their own queued reset. Stale manual text is rejected. Explicit Pause invalidates selections; audio-focus interruption still cancels preparation. Playback-target preferences distinguish library, webpage and empty selections so implicit resumption cannot fall back to a previous offline book after a failed web load.

Deletion runs through an app-only service command and the playback mutex. Queue/progress removal and cascade chapter/book deletion are transactional; checkpoints only save progress for an existing matching book/chapter. Private text deletion resolves a single safe child directory below `filesDir/books`; it never deletes arbitrary database text paths or original import files. Removing an unrelated offline book does not cancel the selected webpage's rendering. Both screens observe a separate active-narration label.

The custom native `ReaderRegressionInstrumentation` lives only in the Android test APK. It exercises the real service, Room, private files, WebView and Read loaded chapter button with original temporary fixtures. Local/CI builds compile that APK; the eight integration cases were run manually in BlueStacks. The instrumentation APK is not published with personal updates.
